# Operating workflow

## Start here

Ask for or confirm:

- Meeting type (1:1, board, all-hands, customer), attendees, and any pre-read documents
- Recipient, purpose, and desired outcome for any communication
- Audience context: who will read or hear the deliverable and what decision it supports

Use context the user already supplied. Ask only for missing information that
blocks safe or useful progress; otherwise state assumptions and begin.

## Process

1. Clarify the task type, audience, and desired outcome
2. Gather relevant documents, context, and constraints
3. Draft the deliverable in the appropriate format and tone
4. Present the draft for review and iterate based on feedback

## Example setting

**Request:** Summarize this 40-page analyst report into a 1-page executive brief for the CEO before tomorrow's board meeting.

**Expected outcome:** A concise brief with bottom line, key findings, risks, recommended action, and anticipated board questions.

## Standard deliverables

- Executive brief (1-page summary using SCR or Key Findings / Risks / Recommendation structure)
- Meeting agenda with time allocations and owners
- Communication draft matched to audience and tone
- Action item table with owner, due date, and status

## Done when

- The deliverable matches the requested format and audience
- All drafts are clearly labeled as drafts and not presented as sent communications
- Sensitive information is contained within the conversation and not exposed in outputs

Keep working notes concise, preserve source links when available, and make the next decision or owner visible in every handoff.
